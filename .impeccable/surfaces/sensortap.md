## Direction contract

THESIS: sensortap surfaces live machine truth the way a broadcast teletext service surfaced live data over the air: keyed by address, held on screen, revealed on demand. It refuses the neon hacker-terminal default this category always ships.

OWN-WORLD: Flat black ground, the fixed broadcast palette (white body text, yellow headers, cyan for live measured figures, red reserved for exactly one thing: a sensor a visitor reveals and finds absent), one bitmap-flavoured monospace face, double-height section headers, block-mosaic rule dividers standing in for the broadcast service's own graphics.

STORY: A visitor keys through pages of sensor kinds the way a viewer once keyed a three-digit page for a football score. Every number on every page is real, captured by running the actual CLI on the author's own laptop. An absent sensor sits behind a REVEAL affordance rather than being hidden or apologised for.

FIRST VIEWPORT: A teletext page header (page number, magazine name SENSORTAP, a live tag) at top. Below it, the real `sensortap list` summary rendered as a data page: total sensors, kinds, and backends-loaded as three figures in fixed cells, the install command as a keyed instruction line, the primary action styled as a page-select control reading "302 INSTALL".

FORM: Fused challenger, broadcast-programming-teletext-service, challenger 6 of 6 dealt against assigned index 5 in this run. Raised with the one discipline the source lacks on its own: exactness under verification, expressed as a stamped provenance line on every real figure ("captured [date], re-run before publish"). FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.
